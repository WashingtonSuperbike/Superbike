Make two edits to `dashboard_refresh()`:

**Edit A — Static sentinel (lines ~50-63 block):**

After `static bool prev_sd_started = true;`, add:

```cpp
static CanStatus prev_can_status = CanStatus::RECEIVING;  // force color push on first refresh (sentinel != boot NO_DATA)
```

Using `RECEIVING` as the sentinel (not `NO_DATA`) ensures the color is pushed unconditionally on the first call to `dashboard_refresh()`, exactly as `prev_sd_started = true` forces the sd_icon update. This is the identical sentinel-mismatch pattern used for every other prev_* variable.

**Edit B — CAN icon refresh block (after the SD icon block):**

Immediately after the closing `}` of the SD icon block (after `prev_sd_started = state.sd_started;`), add:

```cpp
    // -- CAN status icon (CANU-02, D-11) --
    CanStatus can_st = state.can_status.load();
    if (can_st != prev_can_status) {
        lv_color_t can_color;
        if (can_st == CanStatus::RECEIVING) {
            can_color = CLR_RPM_ARC;       // green — actively receiving frames
        } else if (can_st == CanStatus::NO_DATA) {
            can_color = CLR_WARN_YELLOW;   // yellow — no frame in last 3 s
        } else {
            can_color = CLR_WARN_RED;      // red — ERR_PASSIVE or BUS_OFF
        }
        lv_obj_set_style_text_color(w.can_icon, can_color, 0);
        prev_can_status = can_st;
    }
```

Notes:
- Use `.load()` explicitly — `CanStatus` has no implicit conversion operator (unlike `atomic<bool>`)
- The `else` branch handles both `ERR_PASSIVE` and `BUS_OFF` (both map to `CLR_WARN_RED` per D-11)
- Place this block before the closing `}` of `dashboard_refresh()`; it is the last dirty-check block in the function
