3. Create `display/src/SDCard/sd_card.h` with:
   ```cpp
   #pragma once
   #include <esp_display_panel.hpp>
   
   // Forward-declare the board namespace
   using namespace esp_panel::board;
   
   struct DashboardState;  // forward declare
   
   /**
    * Initialize SPI bus for SD card. Must be called AFTER board->begin().
    * Configures CH422G expander pin 4 (SD_CS) as output, disables hardware CS,
    * starts SPI on MOSI=11, CLK=12, MISO=13.
    *
    * @param board  Pointer to the already-initialized Board object (for expander access)
    */
   void sd_init(Board *board);
   
   /**
    * FreeRTOS task: polls SD mount state every 500ms, updates state->sd_started.
    * Pin to Core 0 (not Core 1 — avoids SPI contention with LVGL display).
    * Pass DashboardState* as task parameter.
    */
   void sd_poll_task(void *param);
   ```

4. Create `display/src/SDCard/sd_card.cpp` with:
   - `#include "sd_card.h"`, `#include <SPI.h>`, `#include <SdFat.h>`, `#include "DashboardUI/DashboardUI.h"`
   - Pin defines: `SD_CS 4`, `SD_CLK 12`, `SD_MISO 13`, `SD_MOSI 11`, `SD_DUMMY_CS 4`
     - Note: `SD_CS` is the CH422G expander logical pin 4 (I2C-controlled). `SD_DUMMY_CS` is ESP32 GPIO 4, which is unassigned in all board source files (confirmed safe: LCD uses GPIOs 0-3 only for DATA11-13/DE, not GPIO 4; CAN uses GPIOs 15-16; I2C uses 8-9; RTC interrupt uses 6). SdFat requires a GPIO for its csPin argument — GPIO 4 will be briefly toggled but is unconnected, causing no interference. Do NOT use `SS` (maps to GPIO 10 = LCD DATA4 on this board).
   - File-scope static: `static SdFs sd;` and `static Board *s_board = nullptr;`
   - `sd_init(Board *board)`:
     - Store board pointer: `s_board = board;`
     - Get expander: `auto expander = board->getIO_Expander()->getBase();`
     - Configure expander CS: `expander->pinMode(SD_CS, OUTPUT);` then `expander->digitalWrite(SD_CS, HIGH);`
     - Configure dummy CS GPIO: `pinMode(SD_DUMMY_CS, OUTPUT); digitalWrite(SD_DUMMY_CS, HIGH);`
     - Disable HW CS: `SPI.setHwCs(false);`
     - Start SPI: `SPI.begin(SD_CLK, SD_MISO, SD_MOSI, -1);`
     - Log: `Serial.println("SD SPI initialized");`
   - `static bool do_mount()`:
     - Get expander: `auto expander = s_board->getIO_Expander()->getBase();`
     - Fast-path: if card already healthy, skip re-init:
       `if (sd.card() && sd.card()->errorCode() == 0) return true;`
     - Assert expander CS: `expander->digitalWrite(SD_CS, LOW);`
     - Create config: `SdSpiConfig cfg(SD_DUMMY_CS, SHARED_SPI, SD_SCK_MHZ(25), &SPI);`
       (SD_DUMMY_CS=4 is a safe unused GPIO; expander pin 4 drives actual SD CS independently)
     - Attempt mount: `bool ok = sd.begin(cfg);`
     - If failed, deassert CS: `if (!ok) expander->digitalWrite(SD_CS, HIGH);`
     - Log result: `Serial.printf("SD mount: %s\n", ok ? "OK" : "FAIL");`
     - Return `ok`
   - `sd_poll_task(void *param)`:
     - Cast param: `DashboardState *state = (DashboardState *)param;`
     - Infinite loop with `vTaskDelay(pdMS_TO_TICKS(500))`:
       - Call `bool mounted = do_mount();`
       - If `mounted != state->sd_started`: update `state->sd_started = mounted;` and log the transition

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SPI bus (SD card) | External SD card provides raw SPI data; malformed responses could hang SPI |
| CH422G expander I2C | Shared bus with LCD; incorrect pin config could disable display |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | D (Denial of Service) | sd_poll_task / SPI bus | accept | sd.begin() has internal timeout; poll task runs on Core 0 separate from display. If SPI hangs, display on Core 1 continues. Phase 2 has no file I/O — risk is limited to mount detection. |
| T-02-02 | T (Tampering) | SD card filesystem | accept | Phase 2 performs no file reads/writes — only mount detection. No data is consumed from the card. Phase 3 will address filesystem integrity. |
| T-02-03 | D (Denial of Service) | CH422G expander conflict | mitigate | Reuse existing expander via `board->getIO_Expander()->getBase()` (D-06). Never create second instance. Only touch pin 4 (SD_CS); do not reconfigure pins 1-3, 5. |
</threat_model>
