<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Hardware verification of CSV logging</name>
  <what-built>
Complete Phase 3 implementation: DashboardBatteryVoltages extended with hv_cell_voltages[24], decipherCellsVoltage fixed to write into struct with critical section, narrow SD file API (sd_open/write/sync/close_log_file), and FreeRTOS logging task writing 20 Hz CSV rows with 10-second flush and card removal handling.
  </what-built>
  <how-to-verify>
**Prerequisites:** ESP32-S3 board connected via USB, FAT32/exFAT SD card inserted.

**Step 1 -- Flash and boot:**
```
pio run -e display -t upload
pio device monitor
```
Observe Serial output. Expected:
- "SD SPI initialized"
- "SD state changed: mounted"
- "CSV log: opened YYYY-MM-DD_HHMMSS.csv" (with actual date/time from RTC)

**Step 2 -- Verify CSV creation (LOG-01, LOG-02, LOG-03):**
Wait 15 seconds, then safely remove the SD card. Insert into PC and open the CSV file.
- File name matches `YYYY-MM-DD_HHMMSS.csv` format (LOG-01)
- First line is the header: `elapsed_ms,speed_mph,motor_rpm,motor_current_A,motor_temp_C,mc_temp_C,bms_voltage_V,aux_voltage_V,cell_01_V,...,cell_24_V,thermistor_01_C,...,thermistor_10_C` (LOG-02, LOG-03)
- Header has exactly 42 columns

**Step 3 -- Verify row rate (LOG-04):**
- Count data rows. After 15 seconds expect ~300 rows (15s * 20 Hz).
- Check `elapsed_ms` column: consecutive rows should differ by ~50 ms.

**Step 4 -- Verify flush durability (LOG-05):**
- The file was pulled at 15 seconds (after at least one 10-second flush cycle).
- File should contain valid CSV data (not zero-length or truncated mid-row).

**Step 5 -- Verify card removal handling (LOG-06):**
Re-insert the SD card into the ESP32 board (do not power cycle).
- Serial should print: "CSV log: opened YYYY-MM-DD_HHMMSS.csv" (a NEW filename)
- Wait 5 seconds, then remove card again.
- Serial should print: "CSV log: card removed, file closed"
- Board should NOT reboot or show any Guru Meditation error.
- Check SD card on PC: TWO CSV files should exist (one from first session, one from second).

**Step 6 -- Verify no crash on extended run:**
Re-insert SD card. Let the system run for 60+ seconds. Monitor Serial for any crash or stack overflow messages. The sd_icon should remain white (mounted) throughout.
  </how-to-verify>
  <resume-signal>Type "approved" if all 6 steps pass, or describe which step failed and the observed behavior.</resume-signal>
