**Main task function: `loggingTask(void *param)`**

Per D-03 and D-05:
```cpp
void loggingTask(void *param) {
    DashboardState *state = (DashboardState *)param;
    bool file_open = false;
    uint32_t last_flush_ms = 0;

    while (true) {
        bool sd_now = state->sd_started;

        // Card removal: close file, stop writing
        if (file_open && !sd_now) {
            sd_close_log_file();
            file_open = false;
            Serial.println("CSV log: card removed, file closed");
        }

        // Card insertion (or first iteration with card present): open new file
        if (!file_open && sd_now) {
            char filename[30];
            rtc_get_filename(filename, sizeof(filename));
            if (sd_open_log_file(filename)) {
                logging_write_header();
                file_open = true;
                last_flush_ms = millis();
                Serial.printf("CSV log: opened %s\n", filename);
            }
        }

        // Write row at 20 Hz
        if (file_open && sd_now) {
            logging_write_row(state);

            uint32_t now = millis();
            if ((now - last_flush_ms) >= FLUSH_INTERVAL_MS) {
                sd_sync_log_file();
                last_flush_ms = now;
            }
        }

        vTaskDelay(pdMS_TO_TICKS(LOG_INTERVAL_MS));
    }
}
```

Key design per decisions:
- D-03: polls `state->sd_started` each iteration (volatile bool, no semaphore)
- D-05: `millis()` for elapsed_ms (boot-relative, never resets)
- D-01: logging lives in its own Logging/ module
- D-02: calls narrow API only (never touches SdFs directly)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DashboardState -> CSV file | Logging task reads volatile state and writes to SD card |
| SD card filesystem | File created on removable media readable by any PC |
| Core 0 task preemption | Logging task preemptible by CAN task during hv_cell_voltages read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | I (Info Disclosure) | CSV file on SD card | accept | Telemetry data (voltage, temp, speed) is not sensitive PII. SD card is physically secured on bike. Owner intends to read this data. |
| T-03-06 | D (Denial of Service) | snprintf buffer overflow | mitigate | 512-byte buffer with `len < (int)sizeof(buf)` guard -- row is silently dropped if it exceeds buffer. Calculated worst-case is 287 bytes (75% margin). |
| T-03-07 | T (Tampering) | hv_cell_voltages read race | mitigate | `taskENTER_CRITICAL(&g_cell_voltages_mux)` + `memcpy` in logging_write_row ensures atomic 24-element read |
| T-03-08 | D (Denial of Service) | Card removal during write | mitigate | Narrow API guards with `isOpen()` before write; logging task closes file on `sd_started == false`; no crash on write failure |
| T-03-09 | D (Denial of Service) | Stack overflow in logging task | mitigate | 8192-byte stack (2x calculated worst-case of ~4300 bytes); stack canary will trigger Guru Meditation if exceeded |
</threat_model>
